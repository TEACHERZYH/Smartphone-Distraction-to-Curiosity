# 跨模态信号实验与物联网感知网页教学平台技术说明与使用指南

---

## 1. 平台概述与工程教育背景

### 1.1 研发背景与行业痛点
在传统的电子信息工程、通信工程与物联网专业实验教学中，普遍存在以下三大结构性痛点：
1. **“黑盒化”与“照方抓药”**：学生盲目按照固定步骤连接导线并读取仪器数字，缺乏对底层物理信号调制的因果推演与先验假说（Hypothesis-driven）。
2. **“试凑式调参”与数据失真**：遇到信号失真或通信误码时，学生倾向于在控制面板上同时盲目乱调多个参数（如同时改变频率、占空比与接收门限），无法确定哪项更动主导了系统性能变化，违背了控制变量法的科学实验准则。
3. **团队合作评价“形式化”**：传统实验报告通常仅由一人代笔完成，其余组员“搭便车”（Free-riding），教师无法在课后追溯每位组员的具体操作记录与角色贡献，难以满足国际工程教育认证（ABET）对可追溯证据链的刚性要求。

### 1.2 教学理念：POE+CR 探究循环与 ABET 闭环支撑
为彻底解决上述问题，本平台将建构主义教育学理论与软件工程因果图谱技术相结合，创新性地构建了 **POE+CR (Predict-Observe-Explain-Challenge-Redesign)** 实验教学范式，对标 ABET 学生成果（Student Outcomes）：
* **ABET SO 1（复杂工程问题解决能力）**：要求学生在 `E1_Predict`（先验预测）阶段基于物理公式建立参数数学期望，并在 `E5_Redesign`（再设计）阶段重构系统。
* **ABET SO 5（有效团队协作与领导力）**：平台内置四人轮岗工单引擎，将实验任务解构为**操作员 (Operator)**、**记录员 (Recorder)**、**分析员 (Analyst)** 和 **核验员 (Auditor)** 四类责任角色，并在实验流转中强制轮换与数字签名。
* **ABET SO 6（严谨实验设计与数据判读能力）**：平台在 `E3_Challenge` 阶段强制实施受控单变量实验判定（Valid Inquiry Loop），确保每次调参均有物理机理解释支撑。

### 1.3 极简轻量级自包含部署架构
本平台面向普通高校无线电实验室与创新工坊的真实教学环境研发，遵循“**零外部网络依赖、前后端一体化、毫秒级响应**”的设计哲学：
* 采用 **FastAPI** 异步微框架作为核心服务引擎。
* 前端采用纯原生 **HTML5 / CSS3 / ES6 / Canvas API**，完全摒弃 Vue/React 等繁重前端构建链与对公网 CDN 的依赖，保证在完全断开外网的纯局域网环境下 100% 稳定运行。
* 数据库采用嵌入式 **SQLite3**，自动挂载于操作系统内存临时文件系统（`/tmp`），既消除了配置大型数据库集群的复杂运维负担，又彻底规避了分布式文件系统的 POSIX 锁竞争问题。

## 3. 核心业务模块与技术特性实现细节

### 3.1 Pre-flight 环境准入预检机制
在实验物理信号采集前，由于各小组所用智能手机、平板与笔记本电脑存在硬件底层差异（如不同机型的麦克风默认采样率不一致、局域网 Wi-Fi 抖动），系统设计了自动化的 Pre-flight 检查网关：
1. **音频采样率审计**：校验浏览器 AudioContext 是否精确锁定为 `44,100 Hz` 或 `48,000 Hz`。若采样率异常，声学脉冲测距的互相关峰值定位将产生确定性时钟漂移，系统直接提示校准。
2. **局域网网络时延 (RTT) 审计**：连续探测终端与教学服务器的 Ping 往返时间，阈值严格限定在 `< 20.0 ms`。超过阈值将标红拦截，防止分布式协作时状态同步不同步。
3. **本地沙箱存储审计**：检测本地浏览器配额与临时存储空间 `>= 100 MB`，确保长时间采集信号（如 Wi-Fi CSI 多载波矩阵）时不发生内存溢出截断。
4. **硬件通信串口波特率**：核验微控制器烧录固件的物理串口波特率固定为 `115,200 bps`。

### 3.2 基于 Run Record 的因果数据溯源与 SHA-256 存证模型
平台摒弃了传统实验室软件“只存最终结果”的缺陷，将实验探究过程建模为有向无环图（DAG），每一次点击“提交并固化运行记录”均生成一个独立的不可变记录（Run Record）：
* **亲缘指针 (`parent_run_id`)**：记录当前运行是基于哪一次历史记录改进而来，形成严密的探究演化树。
* **物理参数元组 (`params_json`)**：捕获所有输入物理量（如调制频率、曝光时间、测试物距、滑动窗口大小等）。
* **物理特征量快照 (`features_json`)**：记录算法提取的关键性能指标（如解调信噪比 SNR、误码率 BER、TOF 测距结果、高斯曲率等）。
* **数据指纹摘要 (`data_hash`)**：基于原始采样信号计算截断 SHA-256 校验和（前 16 位），确保实验数据真实可信，彻底杜绝报告作假。

### 3.3 Diff View 差异比对与 Valid Inquiry Loop 判定引擎
这是本平台区别于一切传统数据采集软件的**核心教学专利级技术**。在 `E3_Challenge` 关键挑战阶段，Valid Loop 判定引擎自动触发严格的受控变量审计逻辑：
```python
def evaluate_valid_inquiry_loop(conn, current_params, parent_run_id, stage, explanation_text):
    if stage != "E3_Challenge":
        return False, "非 E3 挑战阶段（作为常规流程推进）。"
    if not parent_run_id or parent_run_id.strip() == "":
        return False, "未指定对比基准 Parent Run ID（无法构建受控对照）。"
    
    # 提取父节点物理参数集并对比差异
    diff_keys = [k for k in all_keys if str(parent_params.get(k)) != str(current_params.get(k))]
    
    # 规则 1：必须有实质更动
    if len(diff_keys) == 0:
        return False, "物理参数未发生实质变更（重复测试）。"
    # 规则 2：严谨单变量控制（核心判定准则）
    if len(diff_keys) > 1:
        return False, f"多变量混乱调参：同时更动了 {len(diff_keys)} 个物理参数 ({', '.join(diff_keys)})，严格仅允许 1 项。"
    # 规则 3：底层物理机理解释字数约束
    if not explanation_text or len(explanation_text.strip()) < 15:
        return False, "机理解释字数不足（需 >= 15 字符）。必须陈述该单变量调参的物理依据。"
    
    return True, f"有效单变量调整循环已确认：{'; '.join(diff_details)}"
```
前端 UI 在比对面板中通过高亮黄底展示发生变化的单变量（Diff View），同时给出绿色成功徽章（`[有效单变量调整循环]`）或红色拦截警告，引导学生回退并重新制定受控测试方案。

### 3.4 四人协作轮岗与责任审计机制 (ABET SO 5)
系统数据库预设 12 个班级小组，每组 4 人，精确划分职责权限：
* **操作员 (Operator)**：负责微控制器跳线连接、激光测距仪校准及手机终端物理对准。
* **记录员 (Recorder)**：负责在工作台录入环境温度、曝光时间等参数，并执行 Pre-flight 检查。
* **分析员 (Analyst)**：负责观察 Canvas 信号波形，提取 FSK 谱峰与 CSI 频偏特征。
* **核验员 (Auditor)**：负责审核机理解释的科学严谨性，并在提交前进行双人复核。
每轮实验结束后，系统支持一键轮换岗位，并将角色履职轨迹固化于导出数据中，供任课教师评估组内协作度。

### 3.5 纯原生 Canvas 实时波形看板
前端内嵌轻量级 Canvas 渲染引擎，利用数学参数方程动态模拟三大模态的信号波形：
* **可见光通信 (VLC)**：模拟高频正弦与方波载波，反映卷帘快门曝光时间变化下的空间光栅条纹周期分布。
* **声学脉冲 (Acoustic)**：模拟双向发射与回波脉冲的时延包络，直观呈现距离变化引起的脉冲时延位移。
* **Wi-Fi 射频感知 (CSI)**：模拟 52 个正交子载波的幅度波动与多径衰落特征。
波形渲染全程在本地浏览器的图形上下文中执行，CPU 占用率低于 2%，不产生任何外部网络传输开销。

### 3.6 教师端全班实时大屏遥测与质控看板 (`/teacher`)
教师端采用深色工业风格大屏设计，提供全班 12 组的宏观遥测与精细化督导能力：
1. **全班全局指标 KPI**：顶部实时汇聚全班总运行次数（Total Runs）、有效循环总数（Valid Loops）、未通过环境预检的待关注小组数。
2. **小组动态卡片网格**：每张小组卡片清晰展示该组当前所处实验模块（VLC/Acoustic/CSI）、当前探究阶段（如 `E3_Challenge`）、有效循环转化率及最后一次活跃时间。
3. **探究异常即时发现**：若某小组长时间停留在某一阶段或持续发生“多变量混乱调参”，教师大屏卡片将呈现明显状态，教师可根据大屏引导精准开展现场台边辅导。
4. **一键穿透证据审查**：点击任意小组卡片，直接在后台调取并打开该组完整的结构化证据包（JSON）。

### 3.7 ABET 认证结构化证据链 JSON 导出
访问 `/api/export/{team_id}` 接口，系统即刻生成符合 ABET SO 1、SO 5、SO 6 评估规范的完整 JSON 档案，包含：
* `export_metadata`：课程编号（EE3042L）、小组 ID、四位成员学号姓名与轮岗职责分配表。
* `preflight_audit`：实验开始时的硬件环境底噪、采样率与网络延迟基准快照。
* `runs_ledger`：该小组从 E1 到 E5 的全部运行流水账，包含每一次调参的参数快照、亲缘父节点、SHA-256 数据指纹、学生机理解释以及平台判定的 `is_valid_loop` 布尔标识。

## 5. 快速部署、日常运维与故障排查指南

### 5.1 依赖环境与快速安装
本工程仅依赖 Python 3.8 及以上标准环境，无需安装任何复杂系统级扩展。在终端中执行：
```bash
cd web_platform_service
pip install -r requirements.txt
```

### 5.2 启动与局域网网络绑定
在实验室教师机或主控工控机上运行：
```bash
# 启动命令（绑定到 0.0.0.0 允许实验室局域网内所有学生机访问）
python3 app.py
```
终端将输出：
```text
INFO:     Started server process [PID]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

### 5.3 局域网组网与学生接入
1. **网络配置**：将教师机与学生端手机/电脑接入实验室同一个无线局域网路由器（推荐 5GHz Wi-Fi 以降低 RTT 时延）。
2. **查询教师机 IP**：
   * Linux/macOS: `ifconfig` 或 `ip addr` (例如 `192.168.1.100`)
   * Windows: `ipconfig`
3. **学生端访问**：在手机或平板移动浏览器中直接输入：`http://192.168.1.100:8000` 即可进入工作台。
4. **教师大屏投影**：在实验室多媒体投影仪上打开：`http://localhost:8000/teacher`。

### 5.4 常见运维故障与自愈对策
* **故障 1：`Address already in use (端口 8000 被占用)`**
  * *原因*：之前残留的 Python 进程未完全退出。
  * *解决*：执行 `lsof -i :8000` 查找进程 PID，执行 `kill -9 <PID>`，然后重新启动 `python3 app.py`。
* **故障 2：`SQLite 数据库 I/O 错误 (disk I/O error)`**
  * *原因*：在部分网络挂载盘（如 NFS、FUSE）上直接运行 SQLite 会因缺少 POSIX 文件锁而报错。
  * *解决*：平台底层已将 `DB_PATH` 锁定在操作系统原生内存临时文件系统 `/tmp/experiment_web_platform_service.db`，天然杜绝锁冲突，无需人工干预。
* **故障 3：学生端 Pre-flight 预检显示“时延偏高 (RTT > 20ms)”**
  * *原因*：多台设备同时下载大文件或 Wi-Fi 信号受到信道同频干扰。
  * *解决*：在路由器后台切换 Wi-Fi 信道至干扰较小的频段（如 5GHz 信道 36 或 149），并确保学生机未开启后台视频流媒体播放。
